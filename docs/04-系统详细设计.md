## 1. 总体架构

系统采用**前后端分离 + 分层架构**，AI 能力以"智能体服务"的形式横向支撑各业务模块。

```text
┌──────────────────────────────────────────────────────────────┐
│                        客户端（Vue 3 SPA）                     │
│  登录 / 看板 / 简历 / 岗位 / 实习 / 面试 / 政策 / 档案          │
└───────────────┬──────────────────────────────┬───────────────┘
                │ HTTP(JSON) + JWT             │ WebSocket(STOMP)
┌───────────────▼──────────────────────────────▼───────────────┐
│                      Nginx（静态资源 + 反向代理）                │
└───────────────┬──────────────────────────────────────────────┘
┌───────────────▼──────────────────────────────────────────────┐
│                    后端服务（Spring Boot 3）                   │
│  ┌────────────┐   ┌──────────────┐   ┌────────────────────┐   │
│  │ Controller │→ │   Service    │→  │ Mapper(MyBatis-Plus)│  │
│  │ 参数/鉴权   │   │ 业务/事务    │   │   SQL / 聚合查询    │  │
│  └────────────┘   └──────┬───────┘   └─────────┬──────────┘   │
│                          │                     │              │
│                   ┌──────▼────────┐   ┌────────▼────────┐     │
│                   │ AgentOrchestr │   │  MySQL 8 业务库  │     │
│                   │  ● 大模型通道  │   │  Redis 热点缓存  │     │
│                   │  ● 规则降级通道│   └─────────────────┘     │
│                   └───────────────┘                           │
└───────────────┬──────────────────────────────────────────────┘
                │ OpenAI 兼容协议（可切换/可离线）
        ┌───────▼─────────────────────────────┐
        │ DeepSeek / 通义千问 / 智谱 / 本地 Ollama │
        └─────────────────────────────────────┘
```

### 1.2 技术选型理由

| 技术 | 选型理由 |
| --- | --- |
| Spring Boot 3 + Java 17 | 企业主流技术栈，生态成熟，便于对接企业级权限与流程需求 |
| MyBatis-Plus | 减少样板 CRUD 代码，内置分页与逻辑删除，SQL 可控 |
| Spring Security + JWT | 无状态认证适配前后端分离，注解式授权表达力强 |
| MySQL + Redis | 满足题目要求；Redis 仅作增强（热点统计/缓存），不可用时自动降级 |
| Vue 3 + TS + Element Plus | 组件齐全、类型安全，适合后台管理系统快速开发 |
| ECharts | 满足看板图表需求，支持饼图/柱状图/折线图与响应式 |
| 大模型 + 本地规则引擎双通道 | 兼顾 AI 能力与"无网可用、可复现"的答辩要求 |

## 3. 关键类设计

### 3.1 智能体调度（核心）

| 类 | 类型 | 职责 |
| --- | --- | --- |
| `AgentOrchestrator` | `@Service` | 场景路由；优先调用大模型，失败/未配置时降级规则引擎；统一产出 `AgentResult` |
| `PromptLibrary` | `@Component` | 按 `AgentScene` 提供 system prompt（含严格 JSON 输出约束） |
| `LlmClient` | 接口 | 大模型抽象，便于替换服务商 |
| `OpenAiCompatibleLlmClient` | `@Component` + 条件装配 | 基于 `RestClient` 调用 OpenAI 兼容接口，`app.ai.enabled=true` 时生效 |
| `LocalRuleEngine` | `@Component` | 确定性规则实现（简历评分、面试三维评分、日志点评、政策抽取式回答） |
| `AgentScene` | 枚举 | 场景标识：简历诊断/岗位匹配/面试评估/政策问答/日志点评 |

```java
AgentOrchestrator.AgentResult result = agentOrchestrator.run(AgentScene.RESUME_DIAGNOSIS, jsonPayload);
boolean aiGenerated = result.aiGenerated();   // true=大模型，false=本地规则
Map<String, Object> data = result.data();     // 结构化结果
```

### 3.2 岗位匹配打分

| 维度 | 权重 | 计算方式 |
| --- | --- | --- |
| 技能匹配 | 40 | 学生技能标签 ∩ 岗位任职要求关键词，按命中比例折算 |
| 学历匹配 | 15 | 岗位学历要求与本人学历比较，不满足按级差扣分 |
| 专业/类别关联 | 15 | 专业字符串与岗位类别、岗位描述的命中情况 |
| 地域与意向 | 15 | 求职意向中的城市/岗位关键词与岗位信息匹配 |
| 档案完整度 | 15 | 姓名、学历、专业、技能、意向五项填写比例 |

输出：`matchScore`（30-99）、`matchLevel`、`matchedSkills`、`missingSkills`、`scoreReasons`。

> 设计取舍：分数用规则计算而非直接交给大模型，保证**可解释、可复现、可答辩**；大模型负责生成自然语言的匹配解读与投递建议。

### 3.3 安全设计

```text
请求 → JwtAuthenticationFilter（解析 Bearer 令牌）
     → LoginUserService.loadUserById（校验用户存在与启用）
     → SecurityContext 写入 LoginUser（含角色）
     → @PreAuthorize 表达式（接口级授权）
     → Service 层数据归属校验（数据级授权）
```

| 风险 | 对策 |
| --- | --- |
| 密码泄露 | BCrypt 加盐哈希；实体 `password` 字段 `@JsonIgnore` |
| 令牌伪造 | HS256 签名；密钥来自配置，生产用环境变量覆盖 |
| 越权访问 | 接口级 `@PreAuthorize` + 资源归属校验（`getOwned`） |
| SQL 注入 | MyBatis-Plus 条件构造器 + 参数化 SQL；`BlockAttackInnerInterceptor` 防全表更新 |
| 文件上传风险 | 扩展名白名单、大小限制、UUID 重命名、独立目录存储 |
| 全表误删 | 逻辑删除 + 防全表更新拦截器 |

### 3.4 异常与日志

- 业务异常 `BizException(code, message)` → `warn` 日志 + 统一响应；
- 参数校验失败 → 汇总字段错误信息返回 40000；
- 未认证/无权限 → 401/403 + 统一 JSON（由 `AuthenticationEntryPoint` 与 `AccessDeniedHandler` 输出）；
- 兜底异常 → `error` 日志（含堆栈）+ 50000 响应，不向前端暴露堆栈。

## 4. 核心流程时序

### 4.1 简历诊断

```text
前端 → ResumeController.diagnose
     → ResumeService.diagnose：校验归属 → 组装 payload（简历正文 + 目标岗位）
     → AgentOrchestrator.run(RESUME_DIAGNOSIS)
         ├─ 大模型可用：PromptLibrary → LlmClient → JSON 解析
         └─ 否则：LocalRuleEngine.generate
     → 回写 resume.score / diagnosis_json
     → 返回 {resumeId, aiGenerated, engine, report}
```

### 4.2 实习审批（含回退）

```text
POST /api/internships/{id}/approve {approve, comment}
 → InternshipService.approve
    → 校验申请存在且 status = RUNNING
    → InternshipNode 状态机：
        通过：MENTOR_REVIEW → COUNSELOR_REVIEW → COLLEGE_REVIEW → PASSED
        驳回：回退上一节点；首节点驳回 → REJECTED
    → 追加 flow_trace_json（操作人/动作/节点/意见/时间）
    → 更新 currentNode / status
```

### 4.3 政策问答（检索增强）

```text
POST /api/policies/ask
 → PolicyService.ask
    → 载入政策库 → PolicyRetriever.retrieve（2-gram + 关键词加权，Top-5）
    → 组装 [序号]上下文 → AgentOrchestrator.run(POLICY_QA)
    → 返回 answer + citations（政策标题/发布单位/日期）+ followUpQuestions
    → HotCacheService 记录提问（Redis 异常静默降级）
```

## 5. 数据库访问设计

- 通用 CRUD 由 `ServiceImpl<Mapper, Entity>` 提供，避免重复代码；
- 看板统计使用 `DashboardMapper` 中的 `@Select` 聚合 SQL，每次请求实时计算；
- 分页统一使用 `PaginationInnerInterceptor`，单页上限 200 条；
- 所有实体含 `deleted` 字段并使用 `@TableLogic` 逻辑删除。

## 6. 前端设计

| 关注点 | 方案 |
| --- | --- |
| 路由 | `createWebHashHistory` + 路由守卫（登录校验、角色校验） |

| 请求 | `api/request.ts` 统一注入令牌、统一拆包 `Result`、401 自动跳登录 |

| 权限 | 前端控制可见性，后端再次鉴权（双重保障） |
