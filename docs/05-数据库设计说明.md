# 数据库设计说明

| 项 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 修订日期 | 2026-09-14 |
| 数据库 | MySQL 8.0（utf8mb4 / InnoDB） |
| 脚本 | 建表 `deploy/sql/schema.sql`，初始化数据 `deploy/sql/data.sql` |

## 1. 设计原则

1. **无外键约束**：关联关系由应用层维护，便于数据清理与后续分库；
2. **逻辑删除**：所有业务表含 `deleted`（0 正常 / 1 删除），实体使用 `@TableLogic`；
3. **统一审计字段**：`create_time`、`update_time` 由数据库默认值与自动更新维护；
4. **状态字段枚举化**：使用固定英文大写值（如 `RUNNING`/`PASSED`），便于程序判断与统计；
5. **索引覆盖高频查询**：账号唯一索引、角色索引、岗位类别/城市索引、学生索引等；
6. **JSON 字段承载半结构化数据**：诊断报告、流程轨迹、面试问答等以 JSON 存储，避免频繁改表。

## 2. 表清单

| 序号 | 表名 | 中文名 | 说明 |

| 7 | `interview_session` | 面试训练表 | 题目、作答与训练报告 |
| 8 | `policy_item` | 就业政策表 | 政策知识库（≥50 条） |

## 3. 实体关系（E-R）

```text
sys_user(学生) 1 ──── n resume
sys_user(学生) 1 ──── n job_application  n ──── 1 job_post
sys_user(HR/辅导员) 1 ──── n job_post（publisher_id）
sys_user(学生) 1 ──── n internship_apply
sys_user(辅导员) 1 ──── n internship_apply（teacher_id）
sys_user(HR)     1 ──── n internship_apply（mentor_id）
internship_apply 1 ──── n internship_log
sys_user(学生) 1 ──── n interview_session
policy_item 独立知识库（被政策问答引用，不建外键）
```

## 4. 核心表字段说明

### 4.1 `sys_user` 用户表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键，自增 |
| `username` | VARCHAR(32) | 登录账号，唯一 |
| `password` | VARCHAR(100) | BCrypt 哈希（禁止明文） |
| `role_code` | VARCHAR(20) | `STUDENT`/`COUNSELOR`/`HR`/`COLLEGE_ADMIN` |
| `college`/`major`/`grade`/`education` | VARCHAR | 学生档案：学院/专业/年级/学历 |
| `skills` | VARCHAR(255) | 技能标签，逗号分隔（岗位匹配关键词来源） |
| `job_intention` | VARCHAR(255) | 求职意向（城市 + 岗位方向） |
| `status` | TINYINT | 1 启用 / 0 停用 |
| `deleted` | TINYINT | 逻辑删除标记 |

索引：`uk_username(username)`、`idx_role(role_code)`。

### 4.2 `job_post` 岗位表

关键字段：`title`、`company_name`、`publisher_id`、`job_category`、`city`、`salary_min`、`salary_max`、
`education_req`、`requirement`（匹配关键词来源）、`deadline`、`status`（1 在招 / 0 下线）。

索引：`idx_category(job_category)`、`idx_city(city)`。

### 4.3 `job_application` 岗位申请表

关键字段：`job_id`、`student_id`、`resume_id`、`match_score`、`status`、`apply_time`。

唯一索引 `uk_job_student(job_id, student_id)`：在数据库层杜绝重复投递（应用层同时校验，双重保险）。

### 4.4 `internship_apply` 实习申请表

关键字段：

| 字段 | 说明 |
| --- | --- |
| `status` | `RUNNING` 审批中 / `PASSED` 通过 / `REJECTED` 驳回 |
| `current_node` | `MENTOR_REVIEW` / `COUNSELOR_REVIEW` / `COLLEGE_REVIEW` / `PASSED` / `REJECTED` |
| `flow_trace_json` | 流程轨迹数组：[{operatorId, action, node, comment, time}] |
| `self_score` / `mentor_score` / `teacher_score` | 三方评分 |
| `final_score` | 加权汇总：自评 20% + 企业导师 40% + 校方 40% |

### 4.5 `policy_item` 政策表

关键字段：`title`、`category`、`region`、`publish_org`、`publish_date`、`content`、`tags`、`view_count`、`status`。

索引：`idx_category(category)`、`FULLTEXT ft_title_content(title, content) WITH PARSER ngram`（中文全文检索预留）。

## 5. 典型统计 SQL（数据看板）

```sql
-- 就业率：已通过实习/就业流程的申请占比
SELECT COUNT(*) AS total,
       SUM(CASE WHEN status = 'PASSED' THEN 1 ELSE 0 END) AS passed
FROM internship_apply WHERE deleted = 0;

-- 行业分布：按岗位类别统计在招岗位数
SELECT job_category AS name, COUNT(*) AS value
FROM job_post WHERE deleted = 0 AND status = 1
GROUP BY job_category ORDER BY value DESC;

-- 薪资分析：各岗位类别平均月薪
SELECT job_category AS name,
       ROUND(AVG((salary_min + salary_max) / 2)) AS avgSalary,
       COUNT(*) AS jobCount
FROM job_post
WHERE deleted = 0 AND salary_min IS NOT NULL AND salary_max IS NOT NULL
GROUP BY job_category ORDER BY avgSalary DESC;

-- 近 7 天投递趋势
SELECT DATE_FORMAT(apply_time, '%m-%d') AS day, COUNT(*) AS value
FROM job_application
WHERE deleted = 0 AND apply_time >= DATE_SUB(CURDATE(), INTERVAL 6 DAY)
GROUP BY day ORDER BY day;
```

## 7. 数据安全与合规

- 学生手机号、邮箱仅用于就业服务，接口按角色限制返回范围；
- 密码只存 BCrypt 哈希，任何接口与日志均不返回密码；
- 简历附件存放于独立目录（容器卷 `upload-data`），通过 `/files/**` 受控访问；
- 生产部署时数据库密码、JWT 密钥、模型 Key 全部通过环境变量注入，不写入代码或文档。
