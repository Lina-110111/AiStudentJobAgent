# 项目开发规范

> 适用范围：本项目全部代码、文档与提交记录。所有成员在提交代码前自检，评审人按本文档把关。

## 1. 目录与分层规范

### 1.1 后端目录

```text
com.campus.jobagent
├── common/        通用能力：统一响应、异常、工具类、文件存储、缓存
├── config/        框架配置：安全、MyBatis-Plus、Jackson、Swagger、WebSocket
├── security/      JWT 认证、登录用户、认证过滤器
├── agent/         智能体：调度器、提示词库、本地规则引擎、大模型客户端
└── modules/       业务模块，每个模块内部再分 controller / service / mapper / entity / dto
```

分层职责（不得越层调用）：

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| `controller` | 参数校验、权限注解、调用 service、包装响应 | 写业务逻辑、直接访问 mapper |
| `service` | 业务规则、事务、调用智能体与其它 service | 返回 `Result`、处理 HTTP 语义 |
| `mapper` | 数据访问（MyBatis-Plus / 注解 SQL） | 写业务判断 |
| `entity` | 与数据库表一一映射 | 承载业务方法（简单转换除外） |

### 1.2 前端目录

```text
src/
├── api/        接口层（唯一允许出现 axios 的地方）
├── router/     路由与菜单（按角色过滤）
├── store/      Pinia 全局状态
├── views/      页面（一个路由一个页面文件）
├── components/ 可复用组件
├── types/      TypeScript 类型声明
└── styles/     全局样式
```

## 2. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 包名 | 全小写、单数 | `modules.resume` |
| 类名 | 大驼峰 | `ResumeService`、`JobMatchScorer` |

| 数据库字段 | 小写下划线 | `job_intention`、`create_time` |
| 前端组件文件 | 大驼峰 `.vue` | `ResumeView.vue`、`EChart.vue` |

| 分支名 | 类型/短横线描述 | `feature/resume-diagnosis` |

## 3. 编码规范

### 3.1 后端（Java 17 / Spring Boot 3）

1. 统一响应：所有接口返回 `Result<T>`，分页返回 `PageResult<T>`；
2. 统一异常：业务异常抛 `BizException`，由 `GlobalExceptionHandler` 兜底转换；禁止把堆栈返回给前端；
3. 参数校验：请求 DTO 使用 `record` + Jakarta Validation 注解（`@NotBlank`、`@Size`、`@Pattern` 等）；
4. 权限控制：接口使用 `@PreAuthorize("hasRole('STUDENT')")` 等表达式；数据权限在 service 层按角色拼接查询条件；
5. 越权防护：查询本人数据必须校验归属（如 `getOwned`），禁止只按 ID 查询后直接返回；
6. 事务：涉及多表写入的方法加 `@Transactional(rollbackFor = Exception.class)`；
7. 日志：使用 `@Slf4j`；`info` 记录关键业务动作，`debug` 记录排查信息，禁止打印密码/令牌；
8. 逻辑删除：表统一含 `deleted` 字段，实体使用 `@TableLogic`；
9. 禁止裸 SQL 拼接；使用 MyBatis-Plus 条件构造器或参数化 SQL；
10. 时间类型统一使用 `LocalDateTime` / `LocalDate`，序列化格式在 `JacksonConfig` 统一为 `yyyy-MM-dd HH:mm:ss`。

### 3.2 前端（Vue 3 + TypeScript）

1. 组合式 API 统一使用 `<script setup lang="ts">`；
2. 接口调用一律走 `src/api/index.ts`，禁止页面内直接 `axios`；
3. 接口返回类型在 `src/types/api.ts` 声明，禁止滥用 `any`（确需动态结构时声明 `Record<string, unknown>`）；
4. 页面样式使用 `<style scoped>`，公共样式放 `src/styles/index.css`；
5. 菜单与路由的可见性由 `router/index.ts` 的 `roles` 控制，后端接口再鉴权一次；
6. 表单必须做前端校验，但后端校验不可省略。

## 4. 接口规范

### 4.1 URL 与动词

- 统一前缀 `/api`，资源名使用复数名词：`/api/resumes`、`/api/jobs`、`/api/policies`；
- 使用 HTTP 动词表达语义：`GET` 查询、`POST` 新增/动作、`PUT` 全量更新、`DELETE` 删除；
- 层级不超过三级：`/api/jobs/{id}/apply`；
- 驼峰参数仅用于查询条件，路径使用中划线或单数：`/api/internships/pending`。

### 4.2 统一响应结构

```json
{
  "code": 20000,
  "message": "操作成功",
  "data": {},
  "timestamp": 1760000000000
}
```

| 状态码区间 | 含义 | 示例 |
| --- | --- | --- |
| 20000 | 成功 | 操作成功 |
| 40000 / 40100 / 40300 / 40400 | 参数错误 / 未认证 / 无权限 / 资源不存在 | 登录状态已失效 |
| 60000-60999 | 业务错误 | 60022 已申请过该岗位、60050 AI 服务调用失败 |
| 50000 | 系统错误 | 系统开小差了 |

### 4.3 分页约定

请求：`pageNum`（从 1 开始）、`pageSize`（默认 10，上限 200）；
响应：`records`、`total`、`pageNum`、`pageSize`。

### 4.4 认证约定

- 登录成功后返回 `token`，前端存入 `localStorage`；
- 后续请求头：`Authorization: Bearer <token>`；
- 令牌有效期默认 12 小时（`app.jwt.expire-minutes`），过期返回 401，前端自动跳转登录页。

### 4.5 接口文档

所有 controller 方法必须写 `@Operation(summary = "...")`，接口 DTO 使用 `@Schema`。
启动后访问 `/swagger-ui.html` 查看与调试；文档变更必须同步提交到 Git。

## 5. 数据库规范

1. 每张表包含：自增主键 `id`、`create_time`、`update_time`、逻辑删除 `deleted`；
2. 字段必须有 `COMMENT`，含义不直观的字段必须注释取值范围；
3. 索引命名：唯一索引 `uk_字段`，普通索引 `idx_字段`；
4. 状态字段使用数值或固定枚举字符串，禁止使用中文；
5. 禁用外键约束，关联关系由应用层维护（便于分库与数据清理）；
6. 结构变更必须同时修改 `deploy/sql/schema.sql`，并在周报中记录。

## 6. Git 与协作规范

详见 [CONTRIBUTING.md](../CONTRIBUTING.md)，核心要点：

- 分支：`main`（交付）/ `develop`（集成）/ `feature/*`、`fix/*`、`docs/*`（日常）；
- 提交信息遵循 `type(scope): subject`，如 `feat(job): 新增岗位匹配打分`；
- 一次提交只做一件事；禁止提交 `target/`、`node_modules/`、`.env`、密钥文件；
- 合并前必须通过 CI（后端编译测试 + 前端构建）；
- 每周六 18:00 前提交项目周报。

## 7. 文档规范

1. 文档统一 Markdown，文件名使用 `序号-名称.md`；
2. 每份文档开头写明：版本号、修订日期、修订人、修订说明；
3. 表格优先：功能清单、字段说明、接口清单必须用表格；
4. 图文一致：文档中的接口、表名、字段名必须与代码完全一致；
5. 禁止出现"待定/略"等无信息量的占位（确实未完成时写"未实现，计划第 X 周完成"）。

## 8. 质量要求（验收自检）

| 项目 | 要求 |
| --- | --- |
| 编译 | `cd backend && mvn -q compile` 无错误 |
| 测试 | `cd backend && mvn test` 全部通过 |
| 前端构建 | `cd frontend && npm run build` 成功产出 `dist/` |
| 部署 | `docker compose up -d --build` 后前端、后端、数据库均健康 |
| 安全 | 无明文密钥入库；越权访问返回 401/403；SQL 参数化 |
| 文档 | `docs/` 七类交付物齐全，接口文档与代码一致 |
