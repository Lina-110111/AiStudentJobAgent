## 1. 说明

1. 本文件是《系统功能分析说明书》的配套部分，回答"**数据项是什么**"：每个数据项的名称、标识、类型、长度、取值范围、来源与业务说明。
2. **全组统一命名约定：数据项标识一律使用大驼峰**（如 `JobIntention`、`MatchScore`），类名同样使用大驼峰，两者完全一致。
3. 为便于与代码对照，本表额外保留一列"**数据库列**"——它是 MySQL 中实际存在的列名（下划线小写），是两个层面的一一映射，不是第二套命名：

| 层面 | 命名规则 | 示例 | 是否可改 |
| --- | --- | --- | --- |
| 数据项标识（文档、类图、类名） | 大驼峰 | `JobIntention` / 类 `JobPost` | 由本组统一约定 |
| 数据库列（schema.sql 实际列名） | 下划线小写 | `job_intention` | 建表脚本已定，改动需同步脚本与代码 |
| Java 属性（可选，实现细节） | 小驼峰 | `jobIntention` | Java 语言规范 |

## 10. 枚举（码表）

> 说明：枚举取值本身是英文大写常量（如 `SUBMITTED`），不属于驼峰命名范围，全表保持与代码一致。

### 10.1 角色编码 `SysUser.RoleCode`

| 取值 | 含义 | 权限范围 |

| COUNSELOR | 辅导员 | 学生档案查询、实习审批、日志批阅、岗位发布、咨询热点 |

| COLLEGE_ADMIN | 院系管理员 | 全院数据看板、用户查询、岗位管理、终审 |

### 10.3 各表 `Status` 含义对照（重要）

### 10.4 实习流程节点流转规则

## 11. 跨表数据项一致性说明

| 数据项 | 出现的实体 | 含义 | 一致性要求 |
| --- | --- | --- | --- |
| `Id` | 全部 8 个实体 | 各表主键 | 各表独立自增，不跨表复用 |
| `UserId` | `Resume` | 简历所属学生 | 指向 `SysUser.Id`，且该用户角色为 STUDENT |
| `StudentId` | `JobApplication`、`InternshipApply`、`InternshipLog`、`InterviewSession` | 学生 | 均指向 `SysUser.Id`，语义与 `UserId` 相同，命名沿用各实体习惯 |
| `JobId` | `JobApplication` | 申请岗位 | 指向 `JobPost.Id` |

| `ApplyId` | `InternshipLog` | 所属实习申请 | 指向 `InternshipApply.Id` |
| `MentorId` | `InternshipApply` | 企业导师 | 指向 `SysUser.Id`，角色应为 HR |
| `TeacherId` | `InternshipApply` | 校内指导教师 | 指向 `SysUser.Id`，角色应为 COUNSELOR |
| `PublisherId` | `JobPost` | 岗位发布人 | 指向 `SysUser.Id`，角色为 HR / COUNSELOR / COLLEGE_ADMIN |
| `Deleted` | 全部 8 个实体 | 逻辑删除 | 统一 0 未删除 / 1 已删除 |

## 12. 数值类与 JSON 类数据项汇总

### 12.1 分数类数据项（易混淆，重点核对）
