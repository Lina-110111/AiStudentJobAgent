## 二、文档版本与维护约定

> **关于文档与代码的关系**：下列文档描述的是**系统完整设计**（全部六个业务模块），
> 而当前脚手架只实现了其中"认证 / 用户档案 / 岗位匹配 / 就业数据看板 + 智能体"这条最小可运行闭环，
> 其余模块为"设计已完成、代码待补"（详见表中各文档的"当前状态"列与仓库 `README.md`）。
> 这样安排是为了让第一周的交付物既完整可用，又不至于文件数量过多；后续按同一套规范逐步补齐即可。

- 文档版本号与代码版本同步：`v0.1`（脚手架阶段）→ `v0.5`（功能联调）→ `v1.0`（验收交付）；
- 接口发生变更时，必须先更新《系统接口设计文档》，再合并代码；
- 数据库结构变更时，必须同步更新 `deploy/sql/schema.sql` 与《数据库设计说明》；
- 文档统一使用 Markdown 编写，提交到 Git 仓库，禁止只在本地保存。
